## 历史问题与验证范围

- 根据用户反馈已修正 Send 入口被订阅状态禁用、Peer 与安全文本重叠的问题；HEX 改为每个字节可选 `0x` 前缀。屏幕和上位机均有运行时开关，屏幕开机默认值可在 Kconfig 配置。键盘使用 LVGL 内置组件并取消全屏拉伸。这些最后的界面修改仅检查 P4 的 `app_ui.c` 语法并运行适用的 Python 检查，没有重新生成板级固件；已有构建日志对应界面修改前的版本。

- 用户日志确认旧 P4 镜像完成屏幕与触摸初始化，但它启用了 compile-only，并在 P4 上错误读取本地 `ESP_MAC_BT`，所以没有进入 Hosted 连接。现已改为默认运行 Hosted，并在连接 C6 后读取远端 BT MAC。
- 后续 P4 日志确认 Hosted 已在 `app_main` 前初始化，SDIO 成功识别 ESP32-C6；当时板上 C6 报告 2.3.0，与主机 2.12.x 不匹配并可能导致后续 RPC 超时。已交付匹配的 C6 2.12.13 完整镜像及独立从机工程。
- 锁定的 ESP-Hosted 2.12.13 通过构造函数在 `app_main` 前初始化；用户已接受这一启动顺序。C6 缺失或异常时，`app_main` 前仍可能等待约 20 秒。
- C6 构建报告上游 `WIFI_CMD_DEFAULT_COUNTRY*` Kconfig 重复定义提示，构建退出码为 0。
- 最小剩余堆、任务栈高水位、射频行为和长时间稳定性没有独立测量记录。
- Python 上位机的软件逻辑已检查；电脑蓝牙扫描、系统配对和 GUI 收发没有单独的实机记录，保留为回归用例。
